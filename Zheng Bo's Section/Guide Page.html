Basic Controls

Understanding the basic controls in Roblox Studio is essential for building and navigating your projects. These controls allow you to move the camera, select objects, and manipulate parts within the 3D workspace.

Before you continue, adjust your graphics level if you have a lower performing device. (File > Studio Settings > Editor Graphics Level)

Camera Controls

  • Right Mouse Button: Hold and drag to rotate the camera view.
  • W, A, S, D Keys: Move the camera forward, left, backward, and right.
  • Q / E Keys: Move the camera down (Q) or up (E).
  • Shift: Hold to move the camera faster.
  • Mouse Scroll Wheel: Zoom the camera in and out.

Object Controls

  • Select Tool (1 key): Click to select parts or models in the workspace.
  • Move Tool (2 key): Allows you to reposition parts along the X, Y, and Z axis.
  • Scale Tool (3 key): Resize parts by dragging handles.
  • Rotate Tool (4 key): Rotate parts around different axes.
  • Transfrom Tool (5 key): The hybrid of Move, Scale and Rotate with an addditional feature to select a plane for movement.

Keyboard Shortcuts

  • Ctrl + Z: Undo the last action.
  • Ctrl + Y: Redo an undone action.
  • F: Focus the camera on the selected object.
  • Ctrl + D: Duplicate the selected object.
  • Delete/Backspace: Remove the selected object from the workspace.

View

They can be found in the 'view' tab of studio.

  • Explorer: Contains all your object locations.
  • Properties: Contains special properties of a currently selected object.
  • Toolbox: Contains all free models that are publicly available. Beware for potential scripts in them as some could contain viruses!
  • Output: Displays all prints and errors from scripts.

Best Practices

  • Use the F key often to quickly center the camera on your work.
  • Keep one hand on the mouse and the other on WASD keys for efficient navigation.
  • Learn keyboard shortcuts to speed up your workflow.
  • Anchor parts when building static structures to prevent unwanted movement.
Note: You can change your keybinds for a more preferred set-up to enhance your effeciency.

Workspace

The Workspace is the root container in Roblox Studio where all 3D objects that appear in the game world are stored. It acts as the main environment where parts, models, and scripts interact.

Key Features

  • Parts and Models: All physical objects in your game are placed inside Workspace.
  • Scripts: Scripts can reference Workspace to access or modify objects.
  • Visibility: Workspace is accessible to both the server and the client.

Server vs Client

Roblox uses a client-server model. The Workspace exists on both sides:

  • Server: Handles game logic, physics, and security.
  • Client: Handles rendering and user interface.

Communication between server and client is done using RemoteEvents and RemoteFunctions.

Best Practices

  • Organize objects into folders for clarity (e.g., “Enemies”, “Items”).
  • Use CollectionService tags to manage groups of objects.
  • Keep Workspace clean by moving non-visual data into ReplicatedStorage or ServerStorage.
Note: Certain objects such as GUI and Sounds do not rely on workspace to work.

Testing

Before publishing you games, every game needs to be tested for any issues to ensure everything works as intended. No game can be made without testing.

To start testing, simply navigate to the top left of your screen. There should be a text saying "Test", with a blue play button, pause button, a red end button and a "PC" icon to switch between server or client view.

Usage

  • Scripting: Ensure that codes correctly controls the game environment.
  • Physics Interaction: Test how a physics part interact around itself.

Physics

Since roblox is also a physics engine, you can apply many physical mechanics into the environment. There are many types of properties that determines a part's interaction

  • Mass: Determines the mass of the part. Changes with material and volume. Can also be altered with "Massless" property and "Density" in "CustomPhysicalProperties
  • Friction: Found in "CustomPhysicalProperties". Determines part's resistance force when sliding.
  • Elasticity: Found in "CustomPhysicalProperties". Determines how much a part bounces.
  • Gravity: A property found in the "Workspace". Determines all part's gravitational force.

Best Practices

  • When writing scripts, make sure to test the code once in a while every few lines.
  • Keep your "Output" open whenever you are testing scripts to spot issues.
Note: Check if all parts in a model is unanchored to allow physics to affect them.

Baseparts

Baseparts are the fundamental building blocks for modeling. They represent physical objects that can be placed in the game world and interacted with by players, scripts, and physics.

Types of Baseparts

  • Part: A simple cube or rectangular block, the most common building element.
  • Wedge: A sloped block useful for ramps and angled surfaces.
  • Cylinder: A round block often used for pillars or wheels.
  • Ball: A spherical part, useful for round objects or physics experiments.
  • Mesh: A unique part that uses an exported mesh from other modeling software. They cannot be union!

Common Properties

  • Colour: Simply changes the colour. Unions need to have "base colour" enabled to fully change its colour.
  • Cast Shadow: Allows shadow to be casted by the object. Invisible objects does not cast shadows unless it is set to a ridiculous amount (Studio Bug).
  • Transparency: Changes the transparency of the object.
  • Anchored: Ensures object cannot be moved physically. Can change its position via scripts.
  • Locked: Cannot be selected by user's cursor but can still block cursor selection. Mainly used in studio mode..
  • Can Collide: Controls if object/players can pass through it.
  • Can Touch: Allows object to detect if it has been 'touched' by any baseparts. Works with 'Can Collide' disabled and used for script events.
  • Can Query: Determine if raycasts can pass through them.

Models

Models is a parent grouping used to contain multiple instances of baseparts and special objects

They can contain

  • RootPart: Any object that is chosen to be a primary part (Found in the Model's properties). This changes the pivot point of the model and they are highlighted in gray.
  • Humanoid: A special object that gives a model humanoid properties. This is how a player is created.

The image below shows an example of a model character, with their rootpart being highlighted in gray.

Best Practices

  • Use Anchored for static structures like buildings.
  • Group parts into Models for easier manipulation.
  • Apply Materials (wood, metal, glass) for realistic appearance.
  • Keep part counts optimized to avoid performance issues in large games.
Note: Baseparts are the core of Roblox building. Every complex model or structure ultimately relies on Baseparts as its foundation.

Union Operation

The most important and customisable basepart in roblox studio. To combine two parts together into one without grouping them, you can use union operations to combine all their properties into one. Note that colours can be different even when unionioned except materials

Regular Unions

A Union combines two or more parts into a single basepart. This is useful for creating complex shapes without grouping. Unlike models, unions merge geometry into one object, which can reduce part count and improve performance. However, note that while colours can differ, materials are unified across the union.

You can union parts using "CTRL + Shift + G". To seperate or undo and union, do "CTRL + Shift + U"

Negative Unions

A Negative Union allows you to subtract one part from another. By toggling a part to negative, it acts like a "cutter" that removes geometry from the positive part. This is especially useful for hollowing out shapes, carving details, or creating openings.

You can toggle parts between positive and negative using "CTRL + Shift + N". To cut out parts, simply union a positive part with a negative part.

Intersect Unions

The Intersect operation keeps only the overlapping volume of selected parts. If two parts share a common area, that intersection becomes the new shape. If no intersection exists, you would receive an error (AKA zero results). This is useful for precise modeling, trimming shapes, or creating complex cutouts.

To intersect two parts, overlap two positive parts then "CTRL + Shift + I".

LuaU

LuaU is Roblox's custom version of the Lua programming language. It is designed for performance, safety, and scalability in Roblox games. LuaU extends standard Lua with new features and optimizations while keeping the language familiar.

Key Features

  • Performance: LuaU is optimized for Roblox's engine, running faster than standard Lua.
  • Type Checking: Supports optional type annotations for safer code.
  • Security: Sandboxed environment prevents unsafe operations.
  • Compatibility: Most Lua 5.1 syntax works, with added Roblox-specific APIs.

LuaU Syntax

                                    
-- Variables
local playerName: string = "David"

-- Functions
local function greet(name: string): string
    return "Hello, " .. name
end

print(greet(playerName))

Differences from Standard Lua

  • Type Annotations: LuaU allows specifying types (string, number, boolean, etc.).
  • Strict Mode: Helps catch errors early by enforcing type rules.
  • Improved Performance: Optimized bytecode and JIT compilation for Roblox.
  • Roblox APIs: Access to objects like Workspace, Players, and ReplicatedStorage.

Script Example

                                    
-- Script to give points when a player touches a part
local part = workspace.Part

part.Touched:Connect(function(hit)
    local player = game.Players:GetPlayerFromCharacter(hit.Parent)
    if player then
        local leaderstats = player:FindFirstChild("leaderstats")
        if leaderstats then
            leaderstats.Points.Value += 10
        end
    end
end)
Note: LuaU is continuously updated by Roblox. Always check the official Roblox Developer Hub for the latest features and changes.

Script Types

Roblox Studio provides three main types of scripts, each serving a different purpose in game development:

  • Server Script: Executes code on the server, handling core game logic and multiplayer synchronization.
  • Local Script: Runs on the client, controlling user interfaces and visual effects.
  • Module Script: Stores reusable functions and data, acting as a shared library for other scripts.

Server Scripts

Server Scripts are the backbone of multiplayer games. They manage gameplay logic, physics, and security. Because they run on the server, changes made here are authoritative and replicated to all players.

Example

This Script changes the colour of the part to red for both the server and all clients 

                                    
-- Place this in ServerScriptService or inside the part
local part = workspace.Part -- replace "Part" with your part's name

-- Change the part's color to red
part.Color = Color3.fromRGB(255, 0, 0)

Local Scripts

Local Scripts run on individual clients. They are used for GUI interactions, camera control, and visual effects. They cannot be placed in Workspace or ServerStorage; instead, they must be inside client containers such as StarterPlayerScripts, StarterCharacterScripts, or PlayerGui.

Since Local Scripts have limited authority, they should never be used to determine critical game outcomes. For server-client communication, use RemoteEvents or RemoteFunctions.

Example

This Local Script changes the colour of the part to red for only the running client 

                                    
-- Place this in StarterPlayerScripts or StarterGui
local part = workspace.Part -- replace "Part" with your part's name

-- Change the part's color to blue (client-side only)
part.Color = Color3.fromRGB(0, 0, 255)

Module Scripts

Module Scripts act as libraries of reusable code and data. They help reduce repetition by allowing developers to define functions once and reuse them across multiple scripts.

Both Server Scripts and Local Scripts can access Module Scripts using the require() function.

Example

This Local Script changes the colour of the part to red for only the running client 

                                    
-- ModuleScript placed inside ReplicatedStorage
local DataModule = {}

DataModule.Items = {
    Sword = {Damage = 25},
    Shield = {Defense = 40}
}

function DataModule.GetItem(name)
    return DataModule.Items[name]
end

return DataModule

-- In another script
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local DataModule = require(ReplicatedStorage:WaitForChild("DataModule"))

local sword = DataModule.GetItem("Sword")
print(sword.Damage) -- prints 25

Best Practices

  • Use Server Scripts for core gameplay logic and security-sensitive operations.
  • Restrict Local Scripts to client-side tasks such as UI and effects.
  • Organize reusable code into Module Scripts to avoid duplication.
  • Always use RemoteEvents and RemoteFunctions for safe server-client communication.
Note: Understanding the role of each script type is crucial. Misusing Local Scripts for server logic or failing to separate reusable code into Module Scripts can lead to performance issues and security vulnerabilities.

Variables

Variables are simple named containers that stores information so that they can be reused later in a later code. They can contain information such as integers, strings, booleans, lists and dictionary.

Example

Below is a code example of variables. Do remember to open your output view!

                                    
-- String variable
local playerName = "John Doe"

-- Number variables
local playerAge = 17
local coins = 250

-- Boolean variable
local isVIP = true

-- Table variable (like a list)
local inventory = {"Sword", "Shield", "Potion"}

-- Print them out
print("Player Name: " .. playerName)
print("Age: " .. playerAge)
print("Coins: " .. coins)
print("VIP Status: " .. tostring(isVIP))
print("Inventory: " .. table.concat(inventory, ", "))

Changeable

Variables are also changeable. This can be used to update a variable to pass down updated information for other codes. You can either replace a variable or add onto a variable

                                    
-- String variable--
local coins = 10
local playerName = "John Doe"

print("Starting coins: " .. coins)
print("Player name: " .. playerName)

-- Change the values
coins = 25
playerName = "James"

print("Updated coins: " .. coins)
print("Updated player name: " .. playerName)

Debugging

In scripting, bugs are almost always garanteed to happen. Some can be easily detected via the output tab with an error. However, value bugs with in correct formats requires heavy testing to be found

The output tab can be found in the middle top of your sceen under the "Script" tab

Types of Bugs

  • Strings: String formating is incorrect.
  • Numbers: Number equation mistakes.
  • Vectors: Using incorrect format when setting vectors.
  • Enums: Workspace is accessible to both the server and the client.
  • Physics: Hardests to fix in studio. Requires other code to negate the issue. Harder to find as it requires heavy play test.

Ways to find

  • Printing: Using prints to return variables allows you to ensure that a code outputs an expected value.
  • Errors: Easily found inside output tab, highlighted in red.
  • Traceback: Traces back to the source of a calculation if functions are used.
  • Heavy Playtesting: Toughest and most exhausting. Requires precise logical understanding to find coding loop holes or physic bugs
Note: Remember to always structure your scripts, think about its interaction with other scripts and always test the same code once in a while to spot issues earlier.

Loops

The most important structure in every single game. They are important to keep all games to keep going. Without loops, everything would only run once.

Usage

There are many ways to use loops in many game features. These can be

  • Self-repeating games
  • Countdowns
  • Moving parts
  • Constant checking
  • NPC behaviours

Types of loops

  • While loop
  • Repeat until
  • For loop
  • For ... in loop
  • While true do
Note: Before running a loop, ensure that task.wait() is used inside the loop to ensure that studio does not crash! This is especially more important in while true do loops.

While loop

                                    
-- Checks for condition before running the code                        
local count = 0
while count < 5 do
    print("Count is", count)
    count = count + 1
end

Repeat until

                                    
-- Checks for condition after running the code
local count = 0
repeat
    print("Count is", count)
    count = count + 1
until count >= 5

For loop

                                    
for i = 1, 5 do
    print("Iteration", i)
end

-- You can also step by a custom increment:
for i = 10, 0, -2 do
    print("Countdown:", i)
end

For ... loop

                                    
local fruits = {"Apple", "Banana", "Cherry"}
for index, fruit in ipairs(fruits) do
    print(index, fruit)
end

While true do

                                    
while true do
    print("Looping every second")
    wait(1)
end

Functions

To ensure that your coding structure remains as neat as possible, you can use functions as a way to reduce code repetition.

Usage

Instead of repeating the same exact code over again, you can use functions to reuse the same code again. Functions also support for reusing of code logic with differing variables.

Example

                                    
-- Define a function
local function greetPlayer(name)
    print("Hello, " .. name .. "! Welcome to the game.")
end

-- Call the function
greetPlayer("John")
greetPlayer("Alex")

With Module Script

Functions can also be stored inside module codes so that other scripts can reuse that exact function, just like an API.

Example

For the test below, ensure you have a module script called MyModule placed inside ReplicatedStorage 

                                    
-- Module Script                                        
local MyModule = {}

function MyModule.Greet(name)
    return "Hello, " .. name .. "!"
end

return MyModule
                                    
                                
                                    
-- Script                                        
local ReplicatedStorage = game:GetService("ReplicatedStorage")
local MyModule = require(ReplicatedStorage:WaitForChild("MyModule"))

-- Call the function from the module
local message = MyModule.Greet("Alex")
print(message)

Events

To allow client-server communication, events can be used to whitelist a certain amount of data to be sent to the server for decision making.

Types of events

There are only two types of events and they can be either bindable or remote

  • Regular Events: Simply sends a data signal over to its listeners.
  • Invoke Functions: Similar to events but sender expects a return value.

Bindable (Server - Server Only)

Events

                                    
-- Sender
BindableEvent:Fire("Hello World")

-- Listener
BindableEvent.Event:Connect(function(message)
    print("Got BindableEvent:", message)
end)

Functions

                                    
-- Sender
local result = BindableFunction:Invoke(10, 20)
print("Result:", result)

-- Listener
BindableFunction.OnInvoke = function(x, y)
    return x + y
end

Remote (Client - Server)

Events Client to Server

                                    
-- Client Sender
RemoteEvent:FireServer("Hello from Client")

-- Server Listener
RemoteEvent.OnServerEvent:Connect(function(player, message)
    print(player.Name .. " sent:", message)
end)

Events Server to Client

                                    
-- Server Sender
RemoteEvent:FireClient(player, "Hello back!") -- Fires To Specific Player Client
RemoteEvent:FireAllClients("Broadcast message") -- Fires To All Player Client


-- Client Listener
RemoteEvent.OnClientEvent:Connect(function(message)
    print("Client received:", message)
end)

Functions (Client to Server)

                                    
-- Client Sender
local result = RemoteFunction:InvokeServer(5, 6)
print("Client got:", result)

-- Server Listener
RemoteFunction.OnServerInvoke = function(player, x, y)
    return x * y
end

Functions (Server to Client)

                                    
-- Server Sender
local result = RemoteFunction:InvokeClient(player, "Ping")
print("Server got:", result)

-- Client Listener
RemoteFunction.OnClientInvoke = function(message)
    return "Pong to: " .. message
end
Note: If you want to communicate to another player client directly, you would need to remotely signal to a server listener. Once that server receives your client message, it would remotely send to the targeted player (If they have a listener).

Raycasting

Raycasts are one of the most essential instance in games. You can imagine it as a instant laser that detects collisions.

It requires a start point and a direction. You cannot simply just state an endpoint position.

Usage

  • Can See: Allows a code to determine a endpoint can be directly seen by an origin point.
  • Detection: Detects what basepart object is in the way when moving from start to end.
  • Projectiles: Used in "Physics" based projectiles by continuously creating short raycast per hop until it hits something.

Example

                                    
-- Assume you have two parts in Workspace: PartA and PartB
local partA = workspace.PartA
local partB = workspace.PartB

-- Define raycast parameters
local raycastParams = RaycastParams.new()
raycastParams.FilterType = Enum.RaycastFilterType.Exclude
raycastParams.FilterDescendantsInstances = {partA} -- ignore the source part itself

-- Calculate direction from PartA to PartB
local origin = partA.Position
local direction = (partB.Position - partA.Position)

-- Perform raycast
local result = workspace:Raycast(origin, direction, raycastParams)

-- Handle result
if result then
    print("Ray hit:", result.Instance.Name)
    if result.Instance == partB then
        print("Direct line of sight to PartB!")
    else
        print("Blocked by:", result.Instance.Name)
    end
else
    print("Ray did not hit anything.")
end
Note: The code above runs only once. To make it run continously, put the code that handles casting and conditions into a while true do loop with a task.wait()

Region3

Making region based interaction can be made via the use of region3. Region3 helps to detect the types of objects within itself.

Usage

Region3 can be used for multiple features.

  • Player zone detection
  • Environment based music
  • King of the hills
  • Item detection in an area

Example

                                    
-- Define the corners of the region
local minCorner = Vector3.new(0, 0, 0)      -- lower corner
local maxCorner = Vector3.new(20, 10, 20)   -- upper corner

-- Create the Region3
local region = Region3.new(minCorner, maxCorner)

-- Expand to grid (optional, useful for terrain operations)
region = region:ExpandToGrid(4)

-- Find parts inside the region
local parts = workspace:FindPartsInRegion3(region, nil, math.huge)

-- Loop through results
for _, part in ipairs(parts) do
    print("Found part:", part.Name)

    -- Check if part belongs to a player character
    local character = part.Parent
    if character and character:FindFirstChild("Humanoid") then
        print("Player detected:", character.Name)
    end
end

Issues

Event though Region3 is useful, it has its own problems.

  • Immutable: Region3 cannot be re-edited after creation
  • Axis-aligned only: Region3 cannot rotate, only axis-aligned boxes.
  • Broad detection: It detects all parts in the region so you would need to manually filter the mout yourself. But its still not great for performance as it still detects parts that you don't need.

Replacement

Instead of Region3, you can instead use GetPartBoundsInBox with OverlapParams to only detect certain parts in a folder/model. This can help with performance if the zone is located in a very decorated environment 

                                    
-- Zone is listed as a Block Basepart                                        
local zonePart = workspace.Zone
local params = OverlapParams.new()
params.FilterType = Enum.RaycastFilterType.Whitelist
params.FilterDescendantsInstances = {workspace.Folder} -- Only Children of "Folder" can be detected

-- This code runs only once, Use a while loop for continuos check
local parts = workspace:GetPartBoundsInBox(zonePart.CFrame, zonePart.Size, params)

Pathfinding

NPCs in roblox are dumb. That is unless you give them pathfinding! This is extremely important for any games that rely on interactive NPCs but also the most difficult to implement.

Usage

Pathfinding can be used for many features, But mainly NPC behaviour

  • Smart NPC behaviour
  • Player Guiding Assistance
  • Navigation Hints

Basics

Before knowing how to create a path, we need to know how to allow npcs to move to a target. The script below simply guides the NPC directly to a target position in a straight line. 

                                    
-- Script inside a model of a chosen NPC                                        
local npc = script.Parent
local humanoid = npc:WaitForChild("Humanoid")
local hrp = npc:WaitForChild("HumanoidRootPart")

-- Replace with your goal object (e.g., a Part named "Goal")
local goal = workspace:WaitForChild("Goal")

-- Loop to keep moving toward the goal
while task.wait(0.1) do
    if goal and goal:IsA("BasePart") then
        -- Move directly toward the goal position
        humanoid:MoveTo(goal.Position)
    end
end

Pathfinding Service

PathfindingService is one of the accessible service to enable this feature. For now we wil run a code that executes once on how pathfinding nodes are created. 

                                    
-- Services
local PathfindingService = game:GetService("PathfindingService")

-- Define start and target positions
local startPos = Vector3.new(0, 5, 0)   -- arbitrary start point
local target = workspace:WaitForChild("Goal") -- a Part named "Goal"

-- Create path object
-- Do note that the parameters affects how the path is calculated.
-- An NPC with low jump power will attempt to jump over a high wall if the parameter states the jump power to be higher than the npc's capability
local path = PathfindingService:CreatePath({
    AgentRadius = 2, -- Determines how minimum distance node has to be from an obstacle
    AgentHeight = 5, -- Determines if the agent can fit under ceilings or through doorways
    AgentCanJump = true, -- Determines if the NPC is allowed to jump. Compliments "Agent Height"
    AgentJumpHeight = 10,   -- Determines the maximum vertical distance the agent can jump up when computing paths
    AgentMaxSlope = 45, -- Determines the maximum angle a path must be to be considered passable by node
})

-- Compute path
path:ComputeAsync(startPos, target.Position)

-- Visualize waypoints
local waypoints = path:GetWaypoints()
for i, waypoint in ipairs(waypoints) do
    local marker = Instance.new("Part")
    marker.Size = Vector3.new(1, 1, 1)
    marker.Shape = Enum.PartType.Ball
    marker.Material = Enum.Material.Neon
    marker.Color = Color3.fromRGB(170, 0, 255) -- neon purple
    marker.Anchored = true
    marker.CanCollide = false
    marker.Position = waypoint.Position
    marker.Parent = workspace

    print("Waypoint " .. i .. " at:", waypoint.Position)
end

Simple NPC Pathfinding

Now lets combine both NPC moving logic with PathfindingService to make a simple and somewhat optimised smart NPC! 

                                    
-- Place this Script inside your NPC model
local npc = script.Parent
local humanoid = npc:WaitForChild("Humanoid")
local hrp = npc:WaitForChild("HumanoidRootPart")

local PathfindingService = game:GetService("PathfindingService")
local RunService = game:GetService("RunService")

-- Replace with your goal object (e.g., a Part named "Goal")
local goal = workspace:WaitForChild("Goal")

-- Settings
local recomputeThreshold = 5 -- studs; only recompute if target moved this far
local lastGoalPos = goal.Position

-- Function to compute and follow path
local function followPath()
    local path = PathfindingService:CreatePath({
        AgentRadius = 2,
        AgentHeight = humanoid.HipHeight + hrp.Size.Y,
        AgentCanJump = true,
        AgentJumpHeight = humanoid.JumpPower / 2,
        AgentMaxSlope = 45,
    })

    path:ComputeAsync(hrp.Position, goal.Position)

    if path.Status == Enum.PathStatus.Success then
        local waypoints = path:GetWaypoints()

        for _, waypoint in ipairs(waypoints) do
            -- Visualize waypoint
            local marker = Instance.new("Part")
            marker.Size = Vector3.new(1, 1, 1)
            marker.Shape = Enum.PartType.Ball
            marker.Material = Enum.Material.Neon
            marker.Color = Color3.fromRGB(170, 0, 255) -- neon purple
            marker.Anchored = true
            marker.CanCollide = false
            marker.Position = waypoint.Position
            marker.Parent = workspace

            -- Move NPC
            humanoid:MoveTo(waypoint.Position)
            humanoid.MoveToFinished:Wait()

            -- Handle jumps
            if waypoint.Action == Enum.PathWaypointAction.Jump then
                humanoid:ChangeState(Enum.HumanoidStateType.Jumping)
            end
        end
    else
        warn("Path failed! NPC cannot reach the goal.")
    end
end

-- Loop to update path only when target moves significantly
RunService.Heartbeat:Connect(function()
    if goal then
        local distMoved = (goal.Position - lastGoalPos).Magnitude
        if distMoved >= recomputeThreshold then
            lastGoalPos = goal.Position
            followPath()
        end
    end
end)
