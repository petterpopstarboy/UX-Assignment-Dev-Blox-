The Three Scripts

Roblox Studio provides three main types of scripts, each serving a different purpose in game development:

  • Server Script: Executes code on the server, handling core game logic and multiplayer synchronization.
  • Local Script: Runs on the client, controlling user interfaces and visual effects.
  • Module Script: Stores reusable functions and data, acting as a shared library for other scripts.

Server Scripts

Server Scripts are the backbone of multiplayer games. They manage gameplay logic, physics, and security. Because they run on the server, changes made here are authoritative and replicated to all players.

Local Scripts

Local Scripts run on individual clients. They are used for GUI interactions, camera control, and visual effects. They cannot be placed in Workspace or ServerStorage; instead, they must be inside client containers such as StarterPlayerScripts, StarterCharacterScripts, or PlayerGui.

Since Local Scripts have limited authority, they should never be used to determine critical game outcomes. For server-client communication, use RemoteEvents or RemoteFunctions.

Module Scripts

Module Scripts act as libraries of reusable code and data. They help reduce repetition by allowing developers to define functions once and reuse them across multiple scripts.

Both Server Scripts and Local Scripts can access Module Scripts using the require() function.

Best Practices

  • Use Server Scripts for core gameplay logic and security-sensitive operations.
  • Restrict Local Scripts to client-side tasks such as UI and effects.
  • Organize reusable code into Module Scripts to avoid duplication.
  • Always use RemoteEvents and RemoteFunctions for safe server-client communication.
Note: Understanding the role of each script type is crucial. Misusing Local Scripts for server logic or failing to separate reusable code into Module Scripts can lead to performance issues and security vulnerabilities.
